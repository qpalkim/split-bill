# split-bill MVP PRD

## 🎯 핵심 정보

**목적**: 인원이 많고 지출 항목이 복잡한 모임의 정산 상황을 입력하면, 별도 가입이나 서버 없이 그 자리에서 정산 결과를 계산해 이미지로 저장할 수 있게 한다.
**사용자**: 인원이 많거나 지출 항목이 복잡해 정산 계산이 번거로운 모임의 총무

## 🚶 사용자 여정

```
1. 참여자 등록 페이지 (서비스 첫 화면)
   ↓ 참여자 명단 입력 후 다음 (입력 즉시 브라우저 로컬에 자동 저장)

2. 지출 내역 페이지
   ↓ "지출 추가" 버튼 클릭

3. 지출 항목 추가/수정 페이지
   ↓ 항목명·금액·결제자·배분 방식 입력 후 저장
   → 지출 내역 페이지로 복귀 (지출 목록에 반영, 반복 가능)

   ↓ "정산 결과 보기" 버튼 클릭

4. 정산 결과 페이지
   ↓ "이미지로 다운로드" → PNG 파일 저장 (서비스 이용 종료)
```

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 참여자 등록 | 모임 이름(선택)과 참여자 명단을 입력해 정산 세션을 시작 | 정산의 시작점이자 필수 진입 절차 | 참여자 등록 페이지 |
| **F002** | 지출 항목 입력 | 항목명, 금액, 결제자를 지정하여 지출 내역 등록 | 정산 계산의 기초 데이터 | 지출 항목 추가/수정 페이지 |
| **F003** | 배분 방식 지정 | 균등 배분(선택한 참여자 전체를 금액 ÷ 인원수로 자동 계산) 또는 항목별 배분(참여자마다 실제 부담 금액을 개별 입력, 입력 합계가 항목 총액과 일치해야 저장 가능) 중 선택 | 인당 지출 금액이 다를 수 있는 실제 모임 지출 패턴을 반영하는 핵심 로직 | 지출 항목 추가/수정 페이지 |
| **F004** | 지출 항목 목록 관리 | 등록된 지출 항목 조회, 수정, 삭제 | 정산 정확도를 위한 필수 관리 기능 | 지출 내역 페이지 |
| **F005** | 정산 결과 자동 계산 | 참여자별 결제 금액과 ExpenseShare 부담 금액 합계를 비교해 순잔액을 산출하고, 최소 송금 횟수로 정리된 "누가 누구에게 얼마" 결과 산출 | 서비스의 핵심 가치(복잡한 계산을 대신 처리) | 정산 결과 페이지 |

### 3. MVP 이후 기능 (제외)

- 회원가입/로그인 및 계정 관리
- 정산방 링크 공유 및 다른 기기·참여자 간 실시간 협업 (백엔드 없는 로컬 전용 도구이므로 제외)
- 과거 정산 내역 히스토리 저장/목록 관리 (1회성 계산 도구로, 여러 세션을 보관할 필요 없음)
- 지출 영수증 이미지 첨부
- 퍼센트/가중치 기반 배분, 한 항목에 결제자 여러 명 지정 등 확장된 배분 방식 (MVP는 균등 배분·개별 금액 직접 입력 두 가지만 지원)
- 정산 완료(송금 확인) 체크 및 알림
- 다중 통화 지원
- 참여자 프로필/아바타 관리

## 🗄️ 데이터 모델

> 별도 서버/DB 없이 아래 구조가 하나의 세션 객체(JSON)로 브라우저 **localStorage**에 저장됩니다.

### Session (정산 세션)
| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 로컬 생성 식별자 | String (UUID) |
| name | 모임 이름 (선택) | String |
| createdAt | 세션 생성 일시 | DateTime |

### Participant (참여자)
| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 고유 식별자 | String (UUID) |
| name | 참여자 이름 | String |

### Expense (지출 항목)
| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 고유 식별자 | String (UUID) |
| title | 항목명 | String |
| amount | 금액 | Number |
| payerId | 결제자 | → Participant.id |
| splitType | 배분 방식 (균등/항목별) | Enum |

### ExpenseShare (지출 부담 배분)
| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 고유 식별자 | String (UUID) |
| expenseId | 대상 지출 항목 | → Expense.id |
| participantId | 부담 참여자 | → Participant.id |
| amount | 해당 참여자의 부담 금액 (균등 배분 시 자동 계산되어 저장, 항목별 배분 시 사용자가 직접 입력) | Number |

> **계산 규칙**
> - 부담 참여자는 항목당 최소 1명 이상 선택해야 저장 가능 (0명 선택 시 저장 불가)
> - 균등 배분: `amount = 지출 금액 ÷ 부담 인원수`, 원 단위 정수로 소수점 이하 내림 처리하며 나눗셈 나머지는 결제자가 추가 부담
> - 항목별 배분: 참여자별 `amount`를 직접 입력하며, 입력한 금액의 합이 지출 항목의 총액(`Expense.amount`)과 정확히 일치해야 저장 가능
> - 참여자는 하나 이상의 `Expense.payerId` 또는 `ExpenseShare.participantId`로 참조되고 있으면 삭제할 수 없음

## 🛠️ 기술 스택

### 🎨 프론트엔드 프레임워크

- **Vite 8** - 프론트엔드 빌드 도구
- **React 19** - UI 라이브러리
- **TypeScript 6** - 타입 안전성 보장
- **React Router 7** - 참여자 등록/지출 내역/지출 입력/정산 결과 페이지 간 클라이언트 사이드 라우팅

- **TailwindCSS v4** (설정파일 없는 새로운 엔진) - 유틸리티 CSS 프레임워크
- **shadcn/ui** - 고품질 React 컴포넌트 라이브러리, UI 구현 시 프리미티브를 최대한 활용
- **Lucide React** - 아이콘 라이브러리
- **UI 정책**: 모바일 화면 전용 제작(태블릿/데스크톱 대응 제외), 다크모드 미지원(라이트 모드 전용)

### 📝 폼 & 검증

- **React Hook Form 7.x** - 폼 상태 관리
- **Zod** - 스키마 검증 라이브러리

### 🖼️ 이미지 생성

- **html-to-image** - 정산 결과 화면(DOM)을 PNG로 변환하여 다운로드 (F006 구현)

### 💾 데이터 저장 (백엔드 없음)

- **Zustand** (`persist` 미들웨어) - 참여자·지출 데이터를 로컬 상태로 관리하고 브라우저 localStorage에 자동 동기화 (F007 구현, 별도 서버/DB 없이 클라이언트에서만 데이터 처리)

### 🚀 배포 & 호스팅

### 📦 패키지 관리

- **npm** - 의존성 관리
